# release-gen

GitHub Action to generate a **next release version** and **release notes** based on commit messages.
Intended to be used only as part of GH action [agilecustoms/release](https://github.com/agilecustoms/release)

## Tech summary

- Language: TypeScript compiled with tsc to `dist/`, committed in as part of release action.
  Production dependencies (semantic-release) are installed at runtime with `npm ci`
- Runtime: GitHub Actions runner, Node.js 24
- Artifact: git tag `v{version}` and floating tags `v{major}`, `v{major}.{minor}`, created by CI on push to `main`

## Usage

Code below is a block from *release* action: part of the inputs are passed through from it,
the other part is generated by it.
Inputs are in snake_case (unlike most GitHub Actions in kebab-case), it is done for integration testing purposes

```yaml
- name: Release generation
  id: release_gen
  if: inputs.dev-release != 'true'
  uses: agilecustoms/release-gen@v5.0.3
  with:
    changelog_file: ${{ inputs.changelog-file }}
    changelog_title: ${{ inputs.changelog-title }}
    floating_tags: ${{ inputs.floating-tags }}
    release_branches: ${{ inputs.release-branches }}
    release_channel: ${{ inputs.release-channel }}
    release_plugins: ${{ inputs.release-plugins }}
    tag_format: ${{ inputs.tag-format }}
    version: ${{ inputs.version }}
    version_bump: ${{ inputs.version-bump }}
```

| Input              | Required | Default                  | Description                                           |
|--------------------|----------|--------------------------|-------------------------------------------------------|
| `changelog_file`   | no       | `CHANGELOG.md`           | Changelog path, empty string disables the changelog   |
| `changelog_title`  | no       |                          | Title of the changelog file (its first line)          |
| `floating_tags`    | no       |                          | Release 1.2.4 also releases 1, 1.2 and latest         |
| `notes_tmp_file`   | no       | `/tmp/release-gen-notes` | Temporary file for release notes                      |
| `release_branches` | no       |                          | Release branches, override `.releaserc.json` branches |
| `release_channel`  | no       |                          | Tag that moves on each release, used with `version`   |
| `release_plugins`  | no       |                          | semantic-release plugins configuration                |
| `tag_format`       | no       | `v${version}`            | Git tag format, applied only to output `git_tags`     |
| `version`          | no       |                          | Explicit version instead of the one from commits      |
| `version_bump`     | no       |                          | Bump version w/o conventional commits                 |

| Output           | Description                                                                                      |
|------------------|--------------------------------------------------------------------------------------------------|
| `channel`        | Release channel: `latest` (main branch), `next` (prerelease), `support` (maintenance)            |
| `version`        | Next version, bare (ex: `1.2.3`), from commits since the last release tag                        |
| `git_tags`       | Space-separated git tags: version, floating versions with tag format (`v1.2.3 v1.2 v1`), channel |
| `notes_tmp_file` | Same as the input, for convenience                                                               |
| `prerelease`     | Whether the release is a prerelease                                                              |
| `tags`           | Space-separated artifact tags (S3 path, Docker tag): `1.2.3 1.2 1` + channel                     |

## How it works

This action is a wrapper for [semantic-release](https://github.com/semantic-release/semantic-release).
Motivation: `semantic-release`, when used as CLI, does not provide `next_version` and `notes` as clear outputs,
just print them. The only way to get these values is to call `semantic-release` as Node.js module
